# Application read isolation evidence

Issue #157 tracks tenant-owned read isolation across the backend, HTTP API, and MCP. `ApplicationReadLeakMatrixE2ETests` supplies a two-populated-tenant broker case in standalone and split API/worker hosts. One signed-in member owns both tenants, and an unrelated signed-in member exercises denial.

The test creates two distinct applications, two system instances, and one current Control draft reference per tenant, plus two application boundary references and two system-instance boundary references. A separate reviewer approves one application boundary version per tenant. The reference-list assertions distinguish that approved version, including its effective date, from the other current draft reference. It verifies positive exact application-revision and system-instance reads over HTTP and MCP. It follows every page of each tenant's top-level application, application-revision, system-instance, application-boundary-reference, and system-instance-boundary-reference lists with `limit=1` over both transports, checking tenant IDs, record IDs, and tenant-specific names or reference text. Cursors issued in tenant A are rejected in tenant B over HTTP and MCP.

For each list and exact read, a foreign application or instance ID under the other tenant returns `NotFound`; the unrelated member is denied. Application-change previews for both tenants return only their own application boundary references, while a foreign application ID and the unrelated member are denied over HTTP and MCP.

Application-change previews over HTTP and MCP check each tenant's boundary and current Control draft reference content, including the Control, Program and entry IDs, and exclude the other tenant's Control. `ApplicationReplayE2ETests.ShouldReplayApplicationAndSystemInstanceReadsAfterWorkerRestartGivenTwoTenants` writes application revisions and system-instance registrations for two tenants while the worker is stopped, checks freshness conflicts, then verifies current application, revision history, and instance reads over HTTP and MCP after a fresh worker resumes the projection. Actor snapshots remain consistent with their legacy fields. Approved Control versions and other preview contexts remain uncovered. The broader #157 inventory is in [tenant-read-leak-matrix.md](tenant-read-leak-matrix.md).
