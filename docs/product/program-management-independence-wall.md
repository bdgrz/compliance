# Remaining program management mutation consumers

The existing retained-history write wall now covers 43 further concrete
management commands: six program/service commands, six boundary commands, four
commitment commands, six criteria-mapping/applicability commands, the criteria
text overlay, evaluation-plan definition, six finding/corrective-action commands,
five readiness commands, and eight distribution/training management commands.

Each command retains its existing owning-client membership, resource ownership
and permission authorizers. Its explicit `IClientManagementMutationRequest`
marker additionally denies a canonical user with actual historical Attest
assignment for that client, including after engagement closure. Actual Advisory
history and Attest history for another client do not cause this denial.

Read, list, preview and history requests remain unmarked. `RecordTrainingCompletion`
records reviewed management evidence under the existing program management
permission; this classification does not restrict a person's course participation.
`AcknowledgePolicy` remains unmarked because its own personal acknowledgement is
allowed under ordinary read authority. On-behalf manager recording requires a
separate conditional source guard; it is not delivered by this consumer subset.

Production-composed request-bus tests prove denial across ten command families,
preserved shared boundary reads, own personal policy acknowledgement with only
ordinary read permission, and Advisory/other-client history positives. Retained
assignment fixtures use the internal engine with explicitly synthetic verified
proof and ratified rules; they provide no real professional authority evidence.

Other management consumers, professional compartment reads and cross-stream
acceptance concurrency remain separate acceptance work. This change adds no
public professional acceptance operation, duty designation, professional access
grant or production rule ratification. The compound criteria remain open.
