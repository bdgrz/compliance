# Personal risk sign-off transport

The existing HTTP-only contracts for `ReviewRiskControlTreatment`, `SubmitRiskTreatmentActionCompletion` and `ReviewRiskTreatmentActionCompletion` now require native `HttpInvocation`, a canonical Bdgrz user and a non-system actor before source or waiver facts are read. The ordinary client-management wall and program grants still apply independently. Risk owner, action editing, treatment proposal and internal reaction commands retain their existing behavior.

Six valid production-composed Direct/MCP calls reproduced successful decisions before the fix. Their focused tests now prove Forbidden and unchanged retained source position and revision. Three native HTTP positives retain canonical attribution, approved control version, fulfilled evidence references and pending/completed action state. Six native HTTP business refusals retain the precise proposer, assigned-reviewer and inactive-waiver reasons. Owner and submitter cannot receive ordinary completion-review assignment; the fixture does not manufacture such an assignment. The explicit nonexistent-waiver cases prove the aggregate's existing exact waiver refusal.

Existing risk source tests use explicit HTTP only for these three decisions, including submission retries with their exact request metadata. Reviewer workflow tests change only the risk completion and control-treatment branches. Ordinary scenario defaults and unrelated personal workflows remain intact.

This is a reserve correction for the existing personal transport contracts under issue 277. It adds no route, wire property, event, grant or deployment requirement, and does not satisfy the broader professional authority or compartment acceptance criteria.
