# Personal readiness and finding closure transport

`DecideReadiness` is management's personal sign-off on one assessment;
`CloseFinding` records the reviewer's own remediation verification and closure.
Both existing contracts are HTTP-only. The source handlers now require personal
HTTP, a canonical Bdgrz actor and a non-system identity before reading client
facts. Existing ordinary authorizers, source ownership/revisions, retained
assessment and corrective-work prerequisites, resolution evidence and exact
separation-of-duties/waiver checks remain mandatory.

Four actual production-composed Direct/MCP requests reproduced valid native
sign-offs before the guards. Two HTTP requests persisted attributed decisions.
The corrected non-HTTP requests refuse without appending source events, while
native HTTP positives and runner/finding-owner separation-of-duties negatives
remain covered. Tests reuse real assessment and completed corrective-work
source fixtures, then compose production AddCompliance dispatch over the shared
retained stores with explicit ordinary permission/membership doubles.

Fourteen existing source and queue decision calls use request-specific HTTP test
helpers. Ordinary scenarios, other decisions and source/projection eligibility
are unchanged. The correction adds no route, tool, DTO marker, wire or event
schema. It supplies no professional authority or production deployment and
consumes reserve rather than an additional management-consumer slice.
