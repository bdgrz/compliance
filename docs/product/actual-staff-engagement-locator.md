# Permanent actual staff source discovery

This is the first directory causality foundation under #277. A registered per-tenant `ActualStaffEngagementLocatorV1` projector discovers actual assignments from retained `ServiceEngagementAcceptanceRecorded` events. It writes only an internal Fitz projection. No HTTP/MCP endpoint, professional grant, acceptance decision, eligibility change, fan-out or reevaluation receipt is added.

Each immutable locator identifies the owning tenant, engagement, canonical staff/user, practice and original accepted request/revision/hash. A separate digest binds the complete acceptance business payload, including the original intent; it does not claim to hash Portia's separately serialized event envelope. It retains the accepted source business sequence, captured directory staff revision, accepted/assignment times and exact source stream, physical resource offset and opaque next cursor. The cursor is retained unchanged; it is not interpreted as an aggregate sequence. Physical offsets may include audit records. The projector uses Portia's supported `ProjectEventAsync` record hook, validates the exact owning ledger stream and open batch identity, and rejects inconsistent tenant, staff, practice, revision or time facts before any row write. Existing rows with the same immutable key must match every source field; conflicting replay is refused.

`acceptance_source_sequence` is the resulting acceptance business sequence (`ExpectedSequence + 1`), consistent with existing causal receipt conventions and the ledger immediately after acceptance. The original predecessor sequence remains bound by the full source payload digest. Invalid maximum predecessor values are rejected before arithmetic. Neither business sequence is a physical offset or a projection cursor.

Rows and their projection checkpoint commit in the same Fitz transaction. Commit failure rolls back both, and retry resumes from the previous checkpoint. The batch checkpoint describes projection progress, separately from each row's historical event cursor. Closure and removal never remove or reinterpret an original locator. Internal bounded pages and exact staff/user indexing support complete traversal; there is no fixed total client or assignment truncation. Per-tenant resources separate clients, including when the same canonical staff identity appears in both. An empty or lagging projection is not proof that no authoritative assignment exists.

The directory gains an internal historical status verifier. It matches the original retained request identity, expected sequence, operation/reason, actor and immutable response. A later status or reactivation cannot reinterpret an earlier source cause. This pure seam verifies retained facts only; the next trusted delivery boundary must independently verify the exact reaction source stream/event. It supplies neither current operator authority nor a public historical read.

Tests compose real production `AddCompliance` registration, retain real directory and client ledger events, and run Portia's real `ProjectorRunner` with the registered component and Fitz transaction. Synthetic internal partner proof/rules are expressly test fixtures, not evidence of real designation or ratification. Tests cover complete 210-row paging, identical-source retry, conflicting immutable replay, source and open-batch tenant fences, permanent history after removal/closure, same canonical staff across two clients, malformed identity/times and failed commit followed by recovery. The additive internal projection/schema does not change the public OpenAPI contract or existing history events.

The next separate foundation must traverse every registered tenant and reconcile both directory status causes and newly accepted sources, preserving checkpoint failures and projection lag. Its durable semantic receipt identity must be based on the exact source cause and affected accepted target, independently of target optimistic concurrency sequence. No cross-realm wildcard read or global snapshot is available in the pinned Portia/Fitz contract. Ratified rule changes, real partner authority, public acceptance/removal adapters and broader professional/compartment consumers remain explicit prerequisites. The compound criteria remain open.
