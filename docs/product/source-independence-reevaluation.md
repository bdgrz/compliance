# Retained service-change reevaluation

The first source-trigger subset for #277 records denial-only assessments when an authorized `RecordNonattestService` changes a client's retained service facts. It uses the existing production request bus, current client administration authority and owning independence ledger. Every active accepted Attest engagement in that ledger receives a distinct receipt in the same optimistic-concurrency transaction as the service cause. Advisory and closed engagements receive no receipt.

Each receipt preserves the causal request and service identity, source sequence, source actor/time, exact accepted snapshot revision and SHA-256, frozen accepted rules, original examination period, complete updated service facts and the IDs considered by the frozen look-back policy. The digest is the lowercase SHA-256 of the accepted view serialized with `ComplianceCoreJsonContext`; receipt identity is UUIDv5 under the causal request using the engagement, accepted revision and digest. Replay recomputes the receipt against authoritative retained facts and refuses altered provenance, policy outcomes, chronology or permission effects.

The policy reference date remains the original examination-period start. `period_start_lookback_decision_code` preserves that bounded judgment. Earlier partner evaluation evidence belongs to the old accepted facts and is never reused as approval of new facts. A new service starting after period start and within the original finite or open-ended period requires fresh review, including when that service has ended. `requires_during_period_review` captures this separately; known impairing evidence in the original look-back remains dominant even when other facts are unclassified. The separate original look-back code still preserves that unknown-classification result; receipt state never conceals the known impairment. All new facts since the acceptance are checked, so a later unrelated source change cannot erase a pending during-period review. Facts starting after a finite period do not expand its bounds.

`compatible`, `review_required` and `impaired` describe this bounded receipt, never a refreshed professional acceptance. Every receipt permanently carries `production_acceptance_blocked = true`. It neither updates accepted proof nor activates grants. Existing accepted-source eligibility also fails closed after a receipt. A compatible period-start look-back is insufficient to restore professional access.

The additive `source_reevaluations` property is returned through the existing authorized client independence history. Historical data without that property produces an empty immutable collection. No new public professional mutation or grant is introduced. Collection snapshots, nested service facts and rules are immutable.

The complete cause-plus-receipts transaction is validated before any event is raised. It is bounded to 48 KiB and a cumulative 1,000 receipts; complete source histories retain their existing 100-service bound. Oversized or invalid changes append neither service nor receipt. Source writer failure and competing expected sequences cannot expose a partial transaction. Receipt source sequence identifies the causal event; ledger sequence includes all physical retained events. `NonattestServiceView` keeps its existing response contract, which has no sequence field. Callers reload `GetClientIndependenceHistory.Sequence` before the next expected-sequence write. Repeating the same attributed request returns the original service response and appends no additional receipt.

This is a first source-trigger subset. Retained reevaluation for assignment lifecycle changes, cross-stream rule/directory changes, current professional partner duty and real professional ratification remain separate prerequisites. The compound #277 criteria remain open, and this partial subset does not reduce their broader forecast.
