# Durable application import omission proposals

Current inventory managers can obtain an explicit source-bound omission preview, personally confirm that preview over HTTP, and read its still-current durable proposal over HTTP or read-only MCP. Contributor staging/preview grants do not grant these manager operations. The freeze command is preparer intent under the accepted attributable import decision policy, analogous to confirming row correlation; it is never retirement approval. Its explicit personal HTTP contract does not classify unrelated inventory writes as personal.

The preview returns the owning tenant/batch/source, exact lifecycle revision, content digest and scoped source position, plus complete missing claims bounded to 200. Clients copy this binding into the freeze request rather than interpreting an opaque cursor or guessing an offset. Shared-target or present-source aliases, invalid/partial sources and changed/unsettled targets remain explicit blockers. Partial coverage produces no inferred omissions. Preview target facts are observations; freeze independently hydrates current targets and reuses the canonical domain checks. Source/batch facts are reread before returning or recording, with source-stream OCC on the write. Neither operation is an atomic downstream approval.

Freeze retains the canonical current preparer's identity, bounded reason and immutable header/rows/SHA seal. Exact request metadata replay appends nothing; changed intent is denied. Tenant/membership/current manager grants and permanent actual Attest management history remain mandatory. Native non-HTTP submission is denied before facts are read. The two reads preserve ordinary authorized shared access and return flattened business DTOs without DomainEvent metadata.

The sealed read uses the existing current source/lifecycle fence. A later source change returns transient Conflict; this API does not promise unrestricted historical proposal reads. A retained seal binds the source observation, not current downstream impact or approval. Both read responses retain `missing_source_retirement_unavailable` and `retirement_impact_unavailable`; proposals create no client grants, retire no target and never unblock import acceptance. Future acceptance must recheck current targets, other-source/manual reliance and complete impact under #464/#492. Raw-byte retention/disposition remains #285. This is partial #195 delivery, with no full retirement, retention, E2E or deployment claim.
